# 章子代理核查细则

章子代理读。判定原则、三档处理、批注写法在 [rules.md](rules.md)，这里只写怎么读、怎么查。


每章分两步，先建表、再查问题：

**第一步：逐段精读，建本章名词表**（`第NN章-名词表.md`）。从头到尾一段一段读，每遇到一个命名对象就登记，并把它在本章的每一种写法和位置（P号）都记下：
- 收录范围见 rules.md 判定原则第 7 条：术语、方法、模型、系统、机构、法规标准、指标、缩写，以及章节标题、图表题、图表中的每一项；
- **以脚本候选为起点**：先读 `source/第NN章-候选.md`（按中心词分组的词组、缩写前后称谓、必搜写法命中）和 `第NN章-变体候选.md`，把候选里的对象先登记上，再逐段精读补候选漏掉的、合并候选切错的。候选不是收录范围，只是起点；
- **按本书名词类别清单逐类核查**（总名词表“〇”）：每一类都要看本章有没有，有就登记，没有在本章名词表末尾写“本类本章无”。研究任务名、方法类别名（监督学习／无监督学习、基于矩阵的方法）、作者方法的组成部分（子问题、阶段、步骤）、概括句和小结里的说法最容易整类漏掉；
- 同一对象的换字（误差修正/误差校正）、增删字（卡尔曼滤波法/卡尔曼滤波算法）、近义写法（隐含层/隐藏层）、全称简称、中英文和缩写，都归到同一条下；**一行只放一个对象**，写法列只放写法和位置，不放备注；
- 概括句、过渡句、小结里的用语，归到它所概括的那个正式说法的条目下；
- 图、表里的文字看排版 PDF 原页登记，不只看提取文字；
- 看着像但其实不是同一个东西的，登记在“非同一对象”里，区分依据必须写内容上的区别和两端原文位置，“标签词不同”“上下位”“不同词”一句话不算依据；**同一个东西在不同环节扮演的角色不同也不算**（第8章“增强图”是 8.2.2 构造出来的图、“增强视图”是 8.2.3 拿来对比的输入，实为同一张图，第一轮据此判“不同对象”放过，编辑指出是不一致）。

**第二步：用本章名词表查本章问题**。
- **判断栏三选一**：一个对象有两种以上写法的，判断栏只能写三种结论之一——①“统一为 X → 问题编号”（每个不一致的位置都写 edit 或批注）；②“不同对象：＜内容上的区别＋两端原文＞”（自动进入放过清单）；③“D-xx”（有倾向的待定）。“一致”“保留”“描述性”“同位语”“概括性”“叙述用法”“各有所指”在多写法行里不许作为结论出现——同一对象在本章出现不同叫法，不能以“描述性说法”为由保留，这正是第一轮最常漏的地方。把几个不同对象放在一行的汇总行（小节题列表、图表各项、参数）写“逐项核对：……”。交活前跑 `check_glossary.py` 到 0 条；
- 每条再对照总名词表（书名、前言、目录及前面各章并入的对象），本章写法与之不一致的同样要报；
- **两张专表**（写在本章名词表末尾，对着漏得最多的两处）：
  - *本章方法称谓表*：作者本章提出的方法（或文科书里作者自己的框架、分期、观点）在全章每一处的叫法逐处列出，类别词（方法／模型／算法／方案／策略／框架）单独一列，对照方法节题的全称和体例逐处判；“该方法……该模型……”同段类别词不一也要报；
  - *并列分项对照表*：子问题、阶段、步骤、模块、贡献列表、“本章从三方面……”这类并列分项，两组以上的左右并排逐字对齐（知识库 F33、F34），项数相同且有一项同名或内容对应的视为同一组对象；
- 然后按下面 A–E 逐项核查（总述与分述、图表与正文、案例内部等不靠名词表也要查）。

**A. 名称（用本章名词表和总名词表）**
- 本章名词表中每个对象的各种写法逐字比较；登记时还要按中心词在本章搜一遍前缀、后缀的变化，避免漏登，并逐处读上下文。
- 上下级标题也要比完整名称：节标题和它下面的小节标题、正文定义指同一对象时，不能默认上级标题的短称是“更泛的说法”。例如 6.1“风电理论发电功率”下的小节和定义都是“风电场理论发电功率”，节标题也应作“风电场”。只有正文确实在上级层面讨论了更宽的对象，才保留短称。
- **章节名有问题时按层级逻辑直接改**（不是把所有标题都过一遍，只在发现标题本身有问题时用：与子节同名、没盖住下面各小节、和正文叫法对不上）：子节题取最短的核心名、去修饰，正文同一说法跟着改；父节题是各子节内容的合称，不与任何子节同名；后一节是前一节的改进时，命名作“修饰语＋前一节名”，让目录一眼看出“基础→改进”。按这套逻辑写确定修订，不挂待确认（2026-11-08 编辑示范：7.2“在线增量低秩塔克分解方案”与 7.2.2 同名 → 7.2“在线低秩塔克分解异常检测方法”、7.2.2“在线塔克分解方法”，7.3＝“基于秩更新的”＋7.2 名）。
- **作者方法的缩写只指一个对象**：同一缩写既括注在整个方法（节题）后、又括注在它的子算法或组成部分后（“算法7.1  ……（MLOTD）”），是所指不一，删去挂在子算法上的那处，作确定修订，不判待确认。节题带不带缩写不是通则（编辑保留了 6.3 节题的“（EC-TR）”），不要为此统一删除。缩写的外文全称只在首次出现处给，后面不再重复括注；已有中文名的指标（真阳性率（TPR））不另补英文全称。
- **法律法规、标准名称核全称**：每次出现都核对是否为正式全称（如《中华人民共和国可再生能源法》、GB/T 7714—2015《信息与文献 参考文献著录规则》），非全称即补全，全书一致（知识库 F23）。
- **通用写法优先**：同一概念全书已有通用写法时，个别变体一律统一（如隐含层→隐藏层、新能源车→新能源汽车）；技术术语以名词委公布名和学界普遍说法为准（F24）。
- **缩写缺全称不批注**（2026-11-10 编辑定）：外文缩写首次出现处缺中文名或外文全称的，不挂批注请作者补。本书名词表里已有该缩写的中文名和全称时，直接补成修订，写法按体例“中文名（英文全称，缩写）”，全称里与缩写对应的字母大小写跟缩写一致，如“长短期记忆（Long Short-Term Memory，LSTM）”；名词表没有就不报。全称与缩写字母对不上、同一缩写前后全称不同，仍按不一致处理。
- **框架图的框题对模块名**：方法框架图里每个大框就是一个模块，框题要和正文模块列表、对应节题逐字比（第8章图8-1 下方大框题“多尺度对比”，装的是两个视图各自的多尺度对比，即 8.2.3“多视图对比学习”模块；第一轮把它当成“多尺度对比”这个概念登记，判同名放过，漏了）。框题只说出模块的一个侧面时，以模块名和节题为准，挂【请作者核实】请改图。
- **图内每一项都与正文逐字比对**：不只比图题和分类名，图中列举的方法名、术语逐项对正文，多字少字都报（如卡尔曼滤波算法／卡尔曼滤波法，F25）。
- **改一处就搜全章**：每补改一处（自己发现或用户指出的），都当成一个写法模式，在全章搜索所有同类变形（如“功率(的)?超短期(的)?预测”“发电功率超短期”），一次改全，并报告搜到几处（F32）。
- **词尾近义字也要比**：只差最后一个字的写法同样是变体，如混沌特性/混沌特征、融合方法/融合方式、预测类型/预测类别；名词表每个条目要逐一列出本章出现的每一种写法，不因并入大条目而省略（F31）。
- **已有批注不等于已处理**：稿中已有的批注（前一轮审查、原稿对照、作者或编辑留下的）只说明有人提过疑点。逐条判断其中的疑点能否凭图表、前后文、规范名称定下来：能定的照样直接修订，并把原批注改为“已改为……”；只有确实需要作者补信息的才保留批注不改。“不要重复已有批注”只是不再写一条内容相同的批注，不是跳过该问题（F30）。
- **图文不一致，先判断哪个对**：分类名、项目名、术语在正文介绍时与图内写法逐字一致，“意思一样”的改写也算不一致（F28）。不一致时先判断图和正文哪个对：图对或两者都说得通，就改正文跟图，作确定修订（图片改不了）；正文对、图错（错别字、大小写、不规范名称、与其他图和正文多处冲突、图中标题没表达准内容），就批注请作者改图。判断依据写进记录或批注（F29）。
- **概括用语与前文正式说法一致**：总述、小结、流程概括中的用词与前文分述逐字一致（如误差修正／误差校正，F26）。
- **列举后有类名时不逐项补后缀**：“盘古、GraphCast、伏羲等气象大模型”中前面用简称不算不一致，不要逐项补“气象大模型”；若坚持用全称，应同时去掉类名（F27，误改反例）。
- **条件分段查边界**：“超过 6 h……低于 6 h……”这类分段，要查边界值（等于 6 h）是否有归属。
- **时效说法核对成书时间**：“目前”“近年来”“未来五年”“今后10年”等，要与成书时间、所引数据的年份一致，过时的请作者更新。
- 补全中心名称后还要检查前缀（如修好“数据语料治理”后还要看前面的“人工智能/AI”）。
- 名称包括公式中的指标符号与图内标签；公式不在提取的文字里时回看原页。只核对命名，不扩展为推导审查。

**B. 总述与分述**（学习目标表、模块表、节首概括、章末回顾）
1. 拆项：每个单元格或概括句拆成模块名、方法、并列项、学习要求。
2. 定位：模块名对节标题，方法和术语对小节标题与定义，“掌握、构建、实现”等要求对实际讲解、案例和代码；要读上下文，不能只看搜索命中。
3. 比名称：按判定原则逐字比较；概括性叙述不要求整句照抄标题。
4. 查顺序：总述逐项列举与后文小标题（或分项）指同一组对象时，列举顺序应与小标题顺序一致，不一致就按小标题顺序调整（作确定修订）；带“如”“等”的举例、或正文说明了另一种排列逻辑的除外。同一列举句改了任一项后整句复读，检查并列项的完整名称（含括注）与格式是否齐整。
5. 查覆盖与层级：是否遗漏主要分项（如总述只写“规则引擎”，标题却是“数据校验与规则引擎设计”）、方法名是否被用途替代、局部操作是否被写成完整流程。名称不一致、覆盖不足、要求超出实际教学分别归类；带“等”“如”的举例不判漏项。
6. 双向回查：概括内容在后文是否落实，后文主要内容是否被准确概括。
7. 每行、每个并列项、每项学习要求都要有判断记录。

**C. 图表与正文**：把图表本体、题注、相邻解释和定义作为一个核对单元，按 [图表内容核对](references/figure-table-content.md) 执行。看不清的图内文字列为待确认，不补造。

**D. 案例内部**：同一案例各部分的对象称谓、带引号的核心判断及其复述（含语序）联查。相同对象、栏目用途、并列搭配可以共同证明对应关系。

**E. 跨章回指**：定位所指章节，只取必要段落或图表核对名称、缩写和定义；找不到、版本不符或回指含糊时注明未核实。回指到尚未审的后续章节时，记入回查清单。
