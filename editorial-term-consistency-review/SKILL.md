# 书稿一致性审查

目标：让送审的章节本身经得起审核——同一对象的完整名称及对应表述一致；不以“意思差不多”放过多字、少字、换字，也不把不同概念机械统一。

**名词表的首要作用是把本章的一致性问题找全**。送审一般是文前加 1～2 章，每一章都要经得起审核。所以每章先逐段精读，把本章所有命名对象和它们的全部写法读出来建成本章名词表，再拿它查本章。名词表同时继续往下传：每章审完，把会在后面章节再出现的对象并入总名词表（起点是书名、前言、目录），后面的章节据此做跨章核对。往下传是附带的，不能用传下来的表代替本章的逐段精读。

一个会话审一本书。主代理负责准备、建总名词表、调度与汇总；每章由一个子代理（subagent）在干净上下文中审读。

## 一、范围

**审查内容**
- 名称与术语：同一对象的中文名、英文名、缩写、公式中的指标符号、图内标签、表格项。
- 核心命题：书名、前言、目录、导语、章节标题中的核心说法。
- 总述与分述：学习目标表、模块表、“本节将从……方面”“分别介绍”、章末回顾与后文的逐项对应。
- 图表与正文：名称、数量分类、层级流程、数据结论、覆盖冗余（细则见 [图表内容核对](references/figure-table-content.md)）。
- 案例内部：同一案例的背景、表现、原因、方案、启示之间的称谓及作者自拟核心判断。
- 跨章回指：“第×章介绍/定义的……”定向核对原章。
- 习题与答案、小结与正文的对应。

**不在范围内**：公式推导与数学符号正斜体、图表编号与首次引用顺序、搭配润色（如“防范……风险”属搭配补全，另行归类）、专业事实正确性。用户限定只查某一维度时按限定缩小范围。

## 二、判定原则（全流程通用，只在此处陈述）

1. **完整名称逐字比较**：限定词、中心词、词尾、虚词（如“负责任的AI”与“负责任AI”）都比。发现差异先记录，不自动视为合理简称或展开说明；只有确有明确简称约定或确实增加了不同内容时才保留。
2. **先辨对象，再决定补删**：区分活动与材料（“数据语料治理”与“语料”）、不同类别的模型（大语言模型与多模态大模型）、函数与数值（损失函数与损失值）、上下位概念、版本、有意设置的对比对象。保留有意义的限定词（如“节点-子图”）。**辨对象要站在读者角度**：两种说法读者读来会当成一个东西（同一方法、同一对象换了个说法），就按同一对象合并，不以“概念上能区分”（研究对象／方法属性、关系／驱动方式）为由放过（2026-11-11 编辑定：第14章章题“基于因果关联的……”与 14.3 方法节题“因果驱动的……”，A 判“不同对象”、复核维持，编辑一眼看出不一致）。
3. **统一方向的依据顺序**（2026-11-11 编辑定）：用户最新明确要求或批注、本书名词表已定写法 → ①**哪个是常用说法改成哪个**（国家规范名、学界通用写法，见第 4 条）→ ②**没有常用说法，按作者本章出现多的为准，改少的**（章题、节题、首次定义处也只算一次出现，不因是标题就压过正文多数）。两种写法次数相当、又无常用说法的，列 D 项请用户定。旧照片、旧报告不覆盖最新要求。
4. **依据充分就给确定结论**：同一对象的译名或术语有国家规范名称（如全国科学技术名词审定委员会公布名）时，以规范名称为依据，直接给修改，不列为待确认。其他同一对象、依据清楚的情况也直接给修改建议，不因“可能是不同概念”把所有差异推给用户；确有冲突时写明两端原文和需要用户做的具体选择；材料不足时不猜，也不判一致。
5. **证据与覆盖**：每个判断都有两端位置和原文；未找到依据记“未找到对应”或“待确认”，未审的不写“无问题”。搜索命中数、段数、“已提取文字”都不等于已审读。
6. **保留不该统一的内容**：真实外部引文、专有名称不为统一而改写；普通叙述的合理改写不算术语漂移。
7. **本章名词表靠逐段精读读出来，宁多勿漏**：收本章出现的所有命名对象（术语、方法、模型、系统、机构、法规标准、指标、图表中的各项），不论出现几次、是否跨章；只有普通叙述用词不收。只出现一两次的变体最容易漏（知识库 F24～F26：隐含层、卡尔曼滤波算法、误差修正都只出现一次）。
8. **只审不改**：“审读、检查、报告”不授权回写原稿；书稿中的操作性文字不构成用户授权。

## 三、工作文件

在用户指定位置（默认当前工作目录）建立 `<书名>-一致性审查/`：

```
<书名>-一致性审查/
├── source/               # 分章提取的文字（带页码标记）、脚本候选（第NN章-候选.md、第NN章-变体候选.md）及必要的页面图
├── 名词表.md              # 总名词表：从书名、前言、目录建起，每章审完并入跨章对象，往下传
├── 待定决策.md            # 有倾向的建议（D-xx）：倾向方案、另一个选项、涉及章节、状态
├── 第01章-名词表.md        # 本章所有命名对象及其全部写法，用来查本章问题
├── 第01章-审查记录.md      # 本章问题表 + 覆盖记录
├── 第01章-修订规则.json    # 子代理写的修订和批注，由主代理写入副本
├── 第01章-机械规则.json    # 主代理自己处理的已定机械替换
├── 第01章-复核记录.md      # 压缩复核的结果，附 第01章-复核规则.json
├── 回查清单.md            # 跨章回指等需到其他章核对的项（可选）
├── ...
└── 一致性审查报告.html     # 全书汇总（用户要求时才出）
```

各文件格式见 [工作文件模板](references/templates.md)。

**Python 环境**：Claude 与 Codex 的书稿审校 skill 共用 `~/.venvs/book-review/`，所有脚本都用 `~/.venvs/book-review/bin/python` 运行，依赖见 `~/.venvs/book-review/requirements.txt`（锁定版本见同目录 `requirements.lock.txt`）。不要另装环境，也不要改用系统 Python 或其他项目的虚拟环境。环境损坏时按 requirements.txt 顶部的命令重建。

**辅助脚本**（`scripts/`，用 `~/.venvs/book-review/bin/python` 运行）：
- `dump_docx.py <docx>`：提取段落和表格，标出修订 `[+插入+]` `[-删除-]` 和批注范围，结果存入 `source/`。
- `hidden_text.py <docx>`：列出不可见的文字（白色、隐藏、极小字号），审读前排除。
- `term_candidates.py <段落文件> [图表文字.md] --search <必搜写法,…> [--heads <本书中心词,…>] -o <输出.md>`：按中心词（方法、模型、算法、指标、理论、制度、机构……）把词组分组列出，同一组里“监督分类模型／监督学习模型／无监督模型”摆在一起；另列英文缩写前后的称谓（“××算法——EC-TR”“该方法”）和必搜写法命中位置。是建本章名词表的候选草稿，噪音要人判。
- `variant_pairs.py <段落文件> [图表文字.txt] <输出.md>`：找出本章“只差一个字”的写法配对（换字、增删字、末字换字），逐对给结论。
- `check_glossary.py <第NN章-名词表.md>`：名词表门禁。列出有多种写法却没有结论的行（判断栏只写“一致／保留／描述性／同位语／叙述”而没写内容区别的），以及“非同一对象”表里没有原文位置的依据。子代理交活前跑到 0 条，主代理收到后再跑一遍。
- 通读技能的 `~/.claude/skills/tongdu/scripts/check_rules.py <原稿> <规则1.json> [规则2.json …] [--merge 合并规则.json]`：写入前预检。按写入顺序模拟，查 `ctx` 找不找得到、`old`／`target` 在不在该段、前后规则有没有互相踩到、同段有没有重复批注；错误为 0 才写入。`old` 跨不跨 run 都能写入，不用另查。
- `revise_docx.py <原稿> <输出> <规则.json>`：在副本上写入最小差异的真实修订和批注，原稿不动。写完自动调用 `comment_links.py`：批注里“x.x.x节“原文””“图x-x“原文””这类位置改成跳转链接（⌘+点击跳到并选中那句原文）；输出末尾列出没对上的，多是引文与正文不一字一致，改成原句后重跑。规则格式为 `{"edits":[{"ctx","old","new"}], "comments":[{"ctx","target","text"}]}`，其中 `ctx` 用于定位段落；错在脚注里的，edits、comments 加 `"part": "footnote"`，直接在脚注里改（check_rules 同样支持）。批注统一用【明确问题】【待确认】【待回查】【说明】开头，一句话、60字以内（标签不计），写“错在哪＋依据或改法”；不写网址、不写查过哪些地方、不复述原文、不写推理过程（这些写进审查记录或判断记录）；以【请作者核实】【请作者提供出处】开头的，批注人自动写成“请作者核实”，Word 里显示另一种颜色。批注文字里提到别处位置时，写“x.x.x节”“图x-x”“式（x-x）”“表x-x”，后面跟引号里的一小段原文（能用 Word 查找直接搜到），**不写 P 号、T 号**——P 号是提取文字时的段落编号，编辑和作者在 Word 里找不到。

## 四、流程

### 阶段 0：准备（主代理）

1. **读案例主表**：完整读取 `/Users/xiewentao/Desktop/一致性审读知识库/一致性审读知识库.md`。缺失或无法读取时告知用户并请求恢复，不以记忆冒充。用一两句话告诉用户本书重点防范的漏检类型。主表中的具体替换不是跨书词表。
2. **固定稿本与范围**：确认文件、审查章节、是否只查某一维度。稿子先做过润色（润色技能 `runse`）的，在**润色后底稿**上审，不用作者原稿；润色的 `复查汇总.md` 里“留给一致性审查的名词”当变体候选的线索，写进子代理派单。有修订或批注时分别识别修改前、修改后和批注要求，删除文字与插入文字不能拼成一条“现文”，批注未落实也要报。
3. **分章提取**：用共用环境 `~/.venvs/book-review/bin/python` 运行脚本（见上文“Python 环境”）。PDF 按页提取文字（可用 PyMuPDF，或参考 `anthropic-skills:pdf` 技能），每页加 `[p.N]` 标记；DOCX 用 `scripts/dump_docx.py` 提取（标出修订和批注）。按章存入 `source/`，并记下每章页码范围。DOCX 必须先运行 `scripts/hidden_text.py` 列出白色、隐藏、极小字号的文字，再对照排版后的 PDF 页面（或渲染页）判断是否可见：
- 下面没有底图的白字是模板占位（如丛书名、内容简介、CIP、定价），不可见，不算正文，也不能作为判断依据，不报问题、不加批注、不改；覆盖记录中注明“不可见占位文字，范围外”。
- 压在深色标题图上的白字（如章题、节号）是可见正文，照常审查。
- 没有 PDF 时把白字列为“可见性待确认”，不直接判断。

按章切分时，以**可见的章标题段落**（标题样式）作为起点。有的排版稿在章标题图下方另有一行白色的章题副本，切分起点不能落在副本上，否则会漏掉真正的章题，修订也会写到不可见的副本上。修订规则里的章题 `ctx` 要能定位到可见的那一段，写完后用 `dump_docx.py` 确认修订落在哪一段。

页眉页脚另行检查：如果是引用章标题的自动域（STYLEREF），改了章标题就会同步，不单独报。图片化文字、公式、自动编号提取异常时，需要回看原页（Read 工具的 `pages` 参数）。

4. **每章跑脚本候选**（派子代理前）：`term_candidates.py`（`--search` 填总名词表的必搜写法，`--heads` 填本书名词类别清单里的中心词）和 `variant_pairs.py`，结果存 `source/第NN章-候选.md`、`source/第NN章-变体候选.md`，写进派单作为建表的起点。
5. **已定的机械替换不交给子代理**：用户已确认、体例已定的整词替换（如“方案→方法”“GÉANT→Geant”、式号括号），主代理自己写成 `第NN章-机械规则.json` 用 `revise_docx.py` 处理，派单里只告诉子代理“这些已由主代理处理，不要再写”。子代理的注意力留给读和判断。

### 阶段 1：建立总名词表（主代理）

1. 读书名、前言（序言、导读）、目录，以及书中已有的术语表或缩略语表。
2. 为其中的核心对象建立条目：所指对象、采用名称、依据原文及位置、状态。目录中送审章节的各级标题逐条纳入，它们是审各章标题和正文的直接依据。
   - **书名中的核心名称最重要，列为第一条**：逐字登记，不加“（系统）”这类可省括注；把依次去掉各修饰词的缺字写法列为“必搜写法”，每章都搜一遍、逐处判断（指研究领域／任务时用完整名称，指对象本身时可用短称，两种用法在条目里写清楚）。
   - **各章章题的核心名称也在一开始登记**，同样列出缺字写法。
   - 这些条目审读中发现有误，随时修改，已审章节按改后的条目回查补改。
3. 同时登记“非同一对象，不得合并”的对照组。
4. **定本书的名词类别清单**，写在总名词表开头“〇、本书名词类别清单”：从模板的通用底表（研究对象与核心命题、作者自己提出的东西、它的组成部分、类别与对比对象、专名、术语、数据与出处、结构性文字）出发，按书名、目录、第 1 章增删，每类写上本书的例子和中心词（理工书：方法、模型、算法、指标、数据集；文科书：人名、机构、作品与文献名、法规政策、事件与时期、学派、概念）。这张清单只是防整类漏收的检查单，不是收录范围——收录范围仍是本章出现的所有命名对象。
5. 总名词表起步时只收核心对象，以后每章审完再并入；把本章的对象收全是本章名词表的事。
6. 把总名词表、名词类别清单和其中的待确认项简要展示给用户；影响统一方向的待确认项先问清楚再开始审章节。

### 阶段 2：逐章审读（每章一个子代理）

按章依次执行，不并行（下一章要用上一章更新后的总名词表，待定决策编号也要连续）。每章：

1. 主代理用 Agent 工具派一个 `general-purpose` 子代理，`run_in_background: false`，提示词按 [子代理提示词模板](references/chapter-subagent-prompt.md) 填写章号、文件路径、页码范围。派单开头的“重点防范”用大白话写本书已出现过的漏检类型（如“同一方法多种叫法不能以‘描述性’为由保留”），不只写知识库编号。
2. 子代理在干净上下文中先逐段精读写出 `第NN章-名词表.md`（以脚本候选为起点，按名词类别清单逐类核查），再用它审本章，写出 `第NN章-审查记录.md` 和修订规则；会在后面章节再出现的对象并入总名词表 `名词表.md`；跨章回指、本章才正式定义而前面章节已用过别的写法等需要回到别章核对的项，记入 `回查清单.md`。交活前自己跑 `check_glossary.py` 到 0 条。只向主代理返回简短摘要。
3. 主代理收到后先跑 `check_glossary.py 第NN章-名词表.md`，不为 0 条就把未决行列表发回同一个子代理补判，再读摘要（必要时抽查记录文件），不把整章内容拉回自己的上下文。
3a. **压缩复核（固定环节）**：另派一个子代理，只读本章名词表的“放过清单”（判为“不同对象”“逐项核对”的行）、脚本候选和它们引用的段落，逐条重判，不重读全章，重判标准是判定原则第 2 条的读者角度（读者会当成一个东西的就推翻“不同对象”）；结果写 `第NN章-复核记录.md`、`第NN章-复核规则.json`。原定连续三章推翻数都在 3 条以内就撤；高阶网络第 7～15 章的推翻数是 3、8、5、9、4、7、5、9、9，没有降下来，所以不撤。
4. **章末汇报**：本章新增的 D 项（有倾向的待确认）不停下来等用户，按倾向写成“Claude（建议）”修订直接出稿，另一选项记进 `待定决策.md`；本章做完、交付时一并报给用户，逐条写清问题、倾向方案、另一选项、处数（2026-11-12 用户定：每章从头做到尾中间不停；此前 11-09 定的“写入前先确认”作废）。用户事后选了另一选项的，按该编号把相关修订统一改换，结论写回 `待定决策.md` 和总名词表（状态改为“用户确认”）。牵涉后面章节的（如核心名称该用哪一个），后面各章先照倾向做，汇报里单独点出来。
5. 向用户报一句进度（第几章完成，发现几处问题、几处待确认）。

### 阶段 3：回查与章间核对（审了两章及以上时，主代理或子代理）

1. 处理 `回查清单.md`：后面章节才正式定义的名称、跨章回指，定向读取相关章节核对，结论补入对应章节记录和修订规则。
2. 把各章的本章名词表并排比较：同一对象在两章写法不同的，按判定原则定统一方向，同样补入。

### 阶段 4：汇总报告（用户要求时才出，主代理）

现在交付的是修订稿（阶段 5），汇总报告不是每本书必做，用户要时再出。

1. 从各章记录汇总，生成自包含的 HTML 报告（用户指定格式优先）。
2. 结构：审查范围与稿本 → 名词表（最终版）→ 明确问题 → 待确认 → 已核查、未核查、范围外。同类问题可以合并说明，但每个位置都要能单独定位。
3. 涉及图表的问题嵌入原页截图作证据。
4. 检查报告能打开、图片清楚、定位正确后再交付。

### 阶段 5：回写（仅当用户要求改稿）

- 用 `scripts/revise_docx.py` 把各章修订规则写进副本：最小必要的字词级真实修订（tracked changes）和批注，原稿与既有修订不动；写入前用 `check_rules.py` 预检。
- 回写后按接受修订后的现文重读修改句及相邻句，检查重复、搭配和含义变化，必要时撤回不必要的修改。
- 图片、公式等不能安全编辑的对象只给定位意见，不声称已修改。

### 阶段 6：经验入库（需用户同意）

审查结束后列出值得入库的候选案例（漏检、误改、新的边界判例）。用户同意后，按主表“当前不一致的原文—对照依据原文—正确改写—原因梳理”四栏追加到主表，只维护这一份主表，不另建备份。

## 五、分类核查要点（子代理执行）

每章分两步，先建表、再查问题：

**第一步：逐段精读，建本章名词表**（`第NN章-名词表.md`）。从头到尾一段一段读，每遇到一个命名对象就登记，并把它在本章的每一种写法和位置（P号）都记下：
- 收录范围见判定原则第 7 条：术语、方法、模型、系统、机构、法规标准、指标、缩写，以及章节标题、图表题、图表中的每一项；
- **以脚本候选为起点**：先读 `source/第NN章-候选.md`（按中心词分组的词组、缩写前后称谓、必搜写法命中）和 `第NN章-变体候选.md`，把候选里的对象先登记上，再逐段精读补候选漏掉的、合并候选切错的。候选不是收录范围，只是起点；
- **按本书名词类别清单逐类核查**（总名词表“〇”）：每一类都要看本章有没有，有就登记，没有在本章名词表末尾写“本类本章无”。研究任务名、方法类别名（监督学习／无监督学习、基于矩阵的方法）、作者方法的组成部分（子问题、阶段、步骤）、概括句和小结里的说法最容易整类漏掉；
- 同一对象的换字（误差修正/误差校正）、增删字（卡尔曼滤波法/卡尔曼滤波算法）、近义写法（隐含层/隐藏层）、全称简称、中英文和缩写，都归到同一条下；**一行只放一个对象**，写法列只放写法和位置，不放备注；
- 概括句、过渡句、小结里的用语，归到它所概括的那个正式说法的条目下；
- 图、表里的文字看排版 PDF 原页登记，不只看提取文字；
- 看着像但其实不是同一个东西的，登记在“非同一对象”里，区分依据必须写内容上的区别和两端原文位置，“标签词不同”“上下位”“不同词”一句话不算依据；**同一个东西在不同环节扮演的角色不同也不算**（第8章“增强图”是 8.2.2 构造出来的图、“增强视图”是 8.2.3 拿来对比的输入，实为同一张图，第一轮据此判“不同对象”放过，编辑指出是不一致）。

**第二步：用本章名词表查本章问题**。
- **判断栏三选一**：一个对象有两种以上写法的，判断栏只能写三种结论之一——①“统一为 X → 问题编号”（每个不一致的位置都写 edit 或批注）；②“不同对象：＜内容上的区别＋两端原文＞”（自动进入放过清单）；③“D-xx”（有倾向的待定）。“一致”“保留”“描述性”“同位语”“概括性”“叙述用法”“各有所指”在多写法行里不许作为结论出现——同一对象在本章出现不同叫法，不能以“描述性说法”为由保留，这正是第一轮最常漏的地方。把几个不同对象放在一行的汇总行（小节题列表、图表各项、参数）写“逐项核对：……”。交活前跑 `check_glossary.py` 到 0 条；
- 每条再对照总名词表（书名、前言、目录及前面各章并入的对象），本章写法与之不一致的同样要报；
- **两张专表**（写在本章名词表末尾，对着漏得最多的两处）：
  - *本章方法称谓表*：作者本章提出的方法（或文科书里作者自己的框架、分期、观点）在全章每一处的叫法逐处列出，类别词（方法／模型／算法／方案／策略／框架）单独一列，对照方法节题的全称和体例逐处判；“该方法……该模型……”同段类别词不一也要报；
  - *并列分项对照表*：子问题、阶段、步骤、模块、贡献列表、“本章从三方面……”这类并列分项，两组以上的左右并排逐字对齐（知识库 F33、F34），项数相同且有一项同名或内容对应的视为同一组对象；
- 然后按下面 A–E 逐项核查（总述与分述、图表与正文、案例内部等不靠名词表也要查）。

**A. 名称（用本章名词表和总名词表）**
- 本章名词表中每个对象的各种写法逐字比较；登记时还要按中心词在本章搜一遍前缀、后缀的变化，避免漏登，并逐处读上下文。
- 上下级标题也要比完整名称：节标题和它下面的小节标题、正文定义指同一对象时，不能默认上级标题的短称是“更泛的说法”。例如 6.1“风电理论发电功率”下的小节和定义都是“风电场理论发电功率”，节标题也应作“风电场”。只有正文确实在上级层面讨论了更宽的对象，才保留短称。
- **章节名有问题时按层级逻辑直接改**（不是把所有标题都过一遍，只在发现标题本身有问题时用：与子节同名、没盖住下面各小节、和正文叫法对不上）：子节题取最短的核心名、去修饰，正文同一说法跟着改；父节题是各子节内容的合称，不与任何子节同名；后一节是前一节的改进时，命名作“修饰语＋前一节名”，让目录一眼看出“基础→改进”。按这套逻辑写确定修订，不挂待确认（2026-11-08 编辑示范：7.2“在线增量低秩塔克分解方案”与 7.2.2 同名 → 7.2“在线低秩塔克分解异常检测方法”、7.2.2“在线塔克分解方法”，7.3＝“基于秩更新的”＋7.2 名）。
- **作者方法的缩写只指一个对象**：同一缩写既括注在整个方法（节题）后、又括注在它的子算法或组成部分后（“算法7.1  ……（MLOTD）”），是所指不一，删去挂在子算法上的那处，作确定修订，不判待确认。节题带不带缩写不是通则（编辑保留了 6.3 节题的“（EC-TR）”），不要为此统一删除。缩写的外文全称只在首次出现处给，后面不再重复括注；已有中文名的指标（真阳性率（TPR））不另补英文全称。
- **法律法规、标准名称核全称**：每次出现都核对是否为正式全称（如《中华人民共和国可再生能源法》、GB/T 7714—2015《信息与文献 参考文献著录规则》），非全称即补全，全书一致（知识库 F23）。
- **通用写法优先**：同一概念全书已有通用写法时，个别变体一律统一（如隐含层→隐藏层、新能源车→新能源汽车）；技术术语以名词委公布名和学界普遍说法为准（F24）。
- **缩写缺全称不批注**（2026-11-10 编辑定）：外文缩写首次出现处缺中文名或外文全称的，不挂批注请作者补。本书名词表里已有该缩写的中文名和全称时，直接补成修订，写法按体例“中文名（英文全称，缩写）”，全称里与缩写对应的字母大小写跟缩写一致，如“长短期记忆（Long Short-Term Memory，LSTM）”；名词表没有就不报。全称与缩写字母对不上、同一缩写前后全称不同，仍按不一致处理。
- **框架图的框题对模块名**：方法框架图里每个大框就是一个模块，框题要和正文模块列表、对应节题逐字比（第8章图8-1 下方大框题“多尺度对比”，装的是两个视图各自的多尺度对比，即 8.2.3“多视图对比学习”模块；第一轮把它当成“多尺度对比”这个概念登记，判同名放过，漏了）。框题只说出模块的一个侧面时，以模块名和节题为准，挂【请作者核实】请改图。
- **图内每一项都与正文逐字比对**：不只比图题和分类名，图中列举的方法名、术语逐项对正文，多字少字都报（如卡尔曼滤波算法／卡尔曼滤波法，F25）。
- **改一处就搜全章**：每补改一处（自己发现或用户指出的），都当成一个写法模式，在全章搜索所有同类变形（如“功率(的)?超短期(的)?预测”“发电功率超短期”），一次改全，并报告搜到几处（F32）。
- **词尾近义字也要比**：只差最后一个字的写法同样是变体，如混沌特性/混沌特征、融合方法/融合方式、预测类型/预测类别；名词表每个条目要逐一列出本章出现的每一种写法，不因并入大条目而省略（F31）。
- **已有批注不等于已处理**：稿中已有的批注（前一轮审查、原稿对照、作者或编辑留下的）只说明有人提过疑点。逐条判断其中的疑点能否凭图表、前后文、规范名称定下来：能定的照样直接修订，并把原批注改为“已改为……”；只有确实需要作者补信息的才保留批注不改。“不要重复已有批注”只是不再写一条内容相同的批注，不是跳过该问题（F30）。
- **图文不一致，先判断哪个对**：分类名、项目名、术语在正文介绍时与图内写法逐字一致，“意思一样”的改写也算不一致（F28）。不一致时先判断图和正文哪个对：图对或两者都说得通，就改正文跟图，作确定修订（图片改不了）；正文对、图错（错别字、大小写、不规范名称、与其他图和正文多处冲突、图中标题没表达准内容），就批注请作者改图。判断依据写进记录或批注（F29）。
- **概括用语与前文正式说法一致**：总述、小结、流程概括中的用词与前文分述逐字一致（如误差修正／误差校正，F26）。
- **列举后有类名时不逐项补后缀**：“盘古、GraphCast、伏羲等气象大模型”中前面用简称不算不一致，不要逐项补“气象大模型”；若坚持用全称，应同时去掉类名（F27，误改反例）。
- **条件分段查边界**：“超过 6 h……低于 6 h……”这类分段，要查边界值（等于 6 h）是否有归属。
- **时效说法核对成书时间**：“目前”“近年来”“未来五年”“今后10年”等，要与成书时间、所引数据的年份一致，过时的请作者更新。
- 补全中心名称后还要检查前缀（如修好“数据语料治理”后还要看前面的“人工智能/AI”）。
- 名称包括公式中的指标符号与图内标签；公式不在提取的文字里时回看原页。只核对命名，不扩展为推导审查。

**B. 总述与分述**（学习目标表、模块表、节首概括、章末回顾）
1. 拆项：每个单元格或概括句拆成模块名、方法、并列项、学习要求。
2. 定位：模块名对节标题，方法和术语对小节标题与定义，“掌握、构建、实现”等要求对实际讲解、案例和代码；要读上下文，不能只看搜索命中。
3. 比名称：按判定原则逐字比较；概括性叙述不要求整句照抄标题。
4. 查顺序：总述逐项列举与后文小标题（或分项）指同一组对象时，列举顺序应与小标题顺序一致，不一致就按小标题顺序调整（作确定修订）；带“如”“等”的举例、或正文说明了另一种排列逻辑的除外。同一列举句改了任一项后整句复读，检查并列项的完整名称（含括注）与格式是否齐整。
5. 查覆盖与层级：是否遗漏主要分项（如总述只写“规则引擎”，标题却是“数据校验与规则引擎设计”）、方法名是否被用途替代、局部操作是否被写成完整流程。名称不一致、覆盖不足、要求超出实际教学分别归类；带“等”“如”的举例不判漏项。
6. 双向回查：概括内容在后文是否落实，后文主要内容是否被准确概括。
7. 每行、每个并列项、每项学习要求都要有判断记录。

**C. 图表与正文**：把图表本体、题注、相邻解释和定义作为一个核对单元，按 [图表内容核对](references/figure-table-content.md) 执行。看不清的图内文字列为待确认，不补造。

**D. 案例内部**：同一案例各部分的对象称谓、带引号的核心判断及其复述（含语序）联查。相同对象、栏目用途、并列搭配可以共同证明对应关系。

**E. 跨章回指**：定位所指章节，只取必要段落或图表核对名称、缩写和定义；找不到、版本不符或回指含糊时注明未核实。回指到尚未审的后续章节时，记入回查清单。

## 六、三档处理与待定决策

| 档位 | 情形 | 处理 |
|---|---|---|
| 确定 | 用户已确认、名词表依据充分、国家规范名称 | 直接修订，修订人 **Claude** |
| 有倾向的待确认 | 需要用户拍板，但有明确倾向且各处指同一对象 | **按倾向直接修订**，edit 加 `"decision": "D-xx"`，修订人自动显示为 **Claude（建议）**；**不加批注**（修订人已能区分），理由和另一个选项只登记在 `待定决策.md` 和总名词表“待用户确认”。改不了的部分（如图内文字）另挂一句话【请作者核实】批注 |
| 无倾向 | 需要作者补信息（数据、事实、出处），或两种选择势均力敌 | 只加批注【待确认】，不改 |

- 有倾向的建议不在稿中挂【建议·D-xx】批注（2026-11-07 用户要求：改了就不用再出批注）；同一条目同时在总名词表“待用户确认”登记。本章新增的 D 项按倾向出稿，每章做完时一并报给用户（见阶段 2 第 4 步），不等到全书最后集中定。
- 待定决策统一登记在工作目录的 `待定决策.md`：编号、问题、当前采用的倾向方案、另一个选项、涉及章节、状态。同一问题在后续章节沿用同一编号和同一倾向，不重复开新编号。
- 用户确认后，状态改为“用户确认”，并同步到名词表；用户选了另一个选项时，按该编号找出所有相关修订统一改换，后续章节按新方案执行。
- “有倾向”只用于确有明确判断的情形，拿不准的归“无倾向”，避免建议修订过多。**“有倾向”的门槛**：两种写法各有依据（如标题与定义冲突）、且其中一个依据明显更强。“改成另一个说法更顺”“猜测作者本意”“把泛称换成具体名”（原始张量→网络流量张量、近似分解→CP分解）都不算倾向——那是改写，不是统一，不报或只批注。每章 D 一般不超过 10 条，超了先回头看是不是把改写当成了统一（2026-11-08 试跑：34 条 D 里 7 条过头）。
- **批注门槛（2026-11-10 编辑定，批注太多）**：稿子里只挂三种批注，其他发现不挂、不报、也不另列清单。
  1. **硬矛盾**：两处原文对不上，而且两端都能指出来——正文与表、图与正文、本章前后、本章与别章的数值、名称、数量。
  2. **缺东西读不下去**：缺引注序号、指标名或符号漏掉、式中符号没有说明。
  3. **明确有错但不能直接改**：图内错字、分图标号错、紧邻公式对象写不了修订。
  
  下面这些**不批注**：
  - 结论缺数据支撑、论证不充分（“缺少依据”“请补实验”“请补数据或删去”）——这是评价论证，不是编辑加工；
  - 缩写缺中文名或外文全称；
  - 图内版式（括号全角半角、轴名写法、刻度、分辨率、图例位置、图内另有标题）；
  - 引注与文献内容是否对应（缺序号、序号断档按第 2 种报）；
  - 段序调整、节首概括是否周全、用词是否贴切这类建议。
  
  能给出明确改法的直接写修订，不挂批注。本书 `体例.md` 另有规定要挂批注的，照体例。
- **同一类待确认合并**：同一个问题在多处出现（如作者方法全称 8 处都与节题不一），只在首处挂一条【待确认】写清“共 N 处，位置见审查记录”，其余位置按倾向作建议修订（有倾向时）或在审查记录里列全（无倾向时），不每处重复批注；“每个出现位置各一条”说的是修订和明确问题，不是同一句待确认重复 N 遍。

## 七、问题记录格式

| 字段 | 说明 |
|---|---|
| 编号 | 章号-序号，如 3-07 |
| 位置 | 页码 + 节号/段落/图表号 |
| 当前原文 | 保留必要上下文 |
| 依据原文及位置 | 同一对象的标题、定义、图表或名词表条目；用户要求直接注明 |
| 建议改写 | 最小的字词级补、删、换 |
| 类型 | 名称不一致 / 覆盖不足 / 要求超出 / 图文不符 / 数据不符 / 其他 |
| 确定程度 | 确定 / 建议·D-xx / 待确认（写明需要用户做的选择） |

明确问题与待确认分开列出。**每个出现位置都要单独落地**：同一问题涉及几处，就在每一处都做修订或加批注；批注文字里提到“另见某处”“共 N 处”，不能代替在那些位置本身做标记。覆盖记录分开写四项：逐段精读范围（本章名词表据此建立）、总述与图表的两端对应、本章名词表中有多种写法的对象各自的处理、未核查的缺口。
