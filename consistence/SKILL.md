# 书稿一致性审查

目标：让送审的章节本身经得起审核——同一对象的完整名称及对应表述一致；不以“意思差不多”放过多字、少字、换字，也不把不同概念机械统一。

**读法照编辑的来**：一段一段读，读到眼熟的名称就翻回去逐字比，不一样当场定结论、当场写改法。每章的名词表就是这样读出来的问题表，不另写审查记录。总名词表只记全书定下来的名称，往后面的章节传。

**分工**：一个会话审一本书。主代理负责准备、建总名词表、派单、登记、写入和汇报；每章的审读交给干净上下文的子代理：名称、图文、其他问题三个同时做，然后一个复核。图文一致性单独由图文子代理逐图逐标签核，图里的字不混在名称里比。

**交付物**：带修订和批注的副本，原稿不动。用户只要审读意见、不要改稿时，停在本章名词表和其他问题清单，不写入副本。

| 谁 | 读什么 |
|---|---|
| 主代理 | 本文件、[判定规则与改法写法](references/rules.md)；做到对应步骤时读 [脚本用法与准备细则](references/scripts.md)、[全书级文件模板](references/templates.md)、[派单模板](references/subagent-prompts.md) |
| 名称子代理 | rules.md、[名称核查细则](references/name-checks.md)、[判例](references/cases.md)、知识库主表 |
| 图文子代理 | rules.md、[逐图核对细则](references/figure-checks.md)、[图表内容核对](references/figure-table-content.md)、知识库主表 |
| 其他问题子代理 | rules.md、[其他问题核查细则](references/other-checks.md)、[图表内容核对](references/figure-table-content.md)、知识库主表 |
| 复核子代理 | rules.md、判例 |

子代理不读本文件，也不读 `待定决策.md`、`回查清单.md`；这两份里和本章有关的行由主代理抄进派单。

## 一、范围

**审查内容**
- 名称与术语：同一对象的中文名、英文名、缩写、公式中的指标符号、图内标签、表格项。
- 核心命题：书名、前言、目录、导语、章节标题中的核心说法。
- 总述与分述：学习目标表、模块表、“本节将从……方面”“分别介绍”、章末回顾与后文的逐项对应。
- 图表与正文：名称、数量分类、层级流程、数据结论、覆盖冗余。
- 案例内部：同一案例的背景、表现、原因、方案、启示之间的称谓及作者自拟核心判断。
- 跨章回指：“第×章介绍/定义的……”定向核对原章。
- 习题与答案、小结与正文的对应。

**不在范围内**：公式推导与数学符号正斜体、图表编号与首次引用顺序、搭配润色、专业事实正确性。用户限定只查某一维度时按限定缩小范围。

## 二、工作目录

建在用户指定位置（默认当前工作目录）：

```
<书名>-一致性审查/
├── source/               # 分章提取的文字、脚本候选、图片文字、试补文件
├── 名词表.md              # 总名词表：只有对象和采用名称，往下传
├── 待定决策.md            # D 项台账，只有主代理读写
├── 回查清单.md            # 跨章待核对的事，只有主代理读写
├── 第NN章-名词表.md        # 本章问题表（名称子代理写，复核改判）
├── 第NN章-名称改法.json    # 名称子代理写：段落号＋旧＋新
├── 第NN章-其他问题.md      # 其他问题子代理写
├── 第NN章-其他改法.json
├── 第NN章-图文核对.md      # 图文子代理写：逐图逐标签
├── 第NN章-图文改法.json
├── 第NN章-复核改法.json    # 复核子代理写，只有推翻的
├── 第NN章-机械规则.json    # 主代理写的已定机械替换
├── 第NN章-修订规则.json    # 脚本由名称改法、其他改法补 ctx 生成
└── 第NN章-复核规则.json    # 脚本由复核改法生成
```

脚本一律用 `~/.venvs/book-review/bin/python` 运行，命令见 [scripts.md](references/scripts.md)。工作目录里有 `本书配置.json` 的书，分章准备、机械规则、合并和交付的固定命令由 bianjia 脚本代跑（`~/.claude/skills/bianjia/README.md`），判断仍照本文件；本书有 `体例.md`（通读技能建的体例表）时，写法照体例。

## 三、流程

### 阶段 0：准备（主代理）

1. **读案例主表**：完整读取 `~/Desktop/一致性审读知识库/一致性审读知识库.md`。缺失或无法读取时告知用户并请求恢复，不以记忆冒充。用一两句话告诉用户本书重点防范的漏检类型。主表中的具体替换不是跨书词表。
2. **固定稿本与范围**：确认文件、审查章节、是否只查某一维度。稿子先做过润色（技能 `runse`）的，在润色后底稿上审，不用作者原稿；润色的 `复查汇总.md` 里“留给一致性审查的名词”写进名称派单。稿中已有修订或批注时，分别识别修改前、修改后和批注要求，删除文字与插入文字不能拼成一条“现文”，批注未落实也要报。
3. **分章提取、排除不可见文字、跑脚本候选**：做法和判断（白字是否可见、章切分起点、页眉页脚）见 scripts.md“准备”一节。产物是每章的 `docx段落.txt`、图片文字、`候选.md`、`变体候选.md`。有图的章，图片导出成文件并照原图转写成 `图片文字.md`（格式见 scripts.md），它是逐图核对的标签清单。
4. **已定的机械替换不交给子代理**：用户已确认、体例已定的整词替换（如“方案→方法”、式号括号），主代理写成 `第NN章-机械规则.json`，派单里告诉子代理“这些已处理，不要再写”。

### 阶段 1：建立总名词表（主代理）

格式见 [templates.md](references/templates.md)。总名词表只记定下来的名称，不记变体出现在哪、哪章改了几处。

1. 读书名、前言（序言、导读）、目录，以及书中已有的术语表或缩略语表。
2. 为核心对象建条目：所指对象、采用名称、适用范围、状态。目录中送审章节的各级标题以目录为准。
   - **书名中的核心名称列为第一条**：逐字登记，不加可省括注；把依次去掉各修饰词的缺字写法列为“必搜写法”，每章都搜一遍、逐处判断（指研究领域或任务时用完整名称，指对象本身时可用短称，两种用法在条目里写清）。
   - 各章章题的核心名称同样登记并列出缺字写法。
3. 登记“非同一对象，不得合并”的对照组。
4. 在开头定“本书名词类别清单”：从模板的通用底表出发，按书名、目录、第 1 章增删。它只是防整类漏收的检查单，不是收录范围。
5. 把总名词表和还没定的事简要展示给用户；影响统一方向的先问清楚再开始审章节，没定的记进 `待定决策.md`。

### 阶段 2：逐章审读

按章依次做，不并行（下一章要用上一章更新后的总名词表）。每章在定了要停的地方停下来问用户（开审前核心名称的统一方向；复核后、写入前本章的 D 项和体例待定项），其余步骤连着做。子代理都是干净上下文、等它返回（Claude Code 里是 Agent 工具的 `general-purpose` 类型，不用 `fork`，fork 会把主会话整段带进去）；派单按 [派单模板](references/subagent-prompts.md) 填，“重点防范”用大白话写本书已出现过的漏检类型。

1. **同时派名称、图文、其他问题三个子代理**（本章没有图时不派图文）。派单里抄上与本章有关的 D 项、回查项，各给一个不重叠的 D 项起号。
   - 名称子代理交回 `第NN章-名词表.md`、`第NN章-名称改法.json`，并把后面章节还会出现的对象并入总名词表。
   - 图文子代理交回 `第NN章-图文核对.md`、`第NN章-图文改法.json`。
   - 其他问题子代理交回 `第NN章-其他问题.md`、`第NN章-其他改法.json`。
2. **主代理收活**：
   - 跑名词表门禁，三项不为 0 就把输出发回名称子代理补；跑图文门禁（`fig_gate.py gate`），四项不为 0 就发回图文子代理补。
   - 把其他问题清单、图文核对里“顺带看到的名称不一致”逐条在本章名词表里搜；表里没有的，发回名称子代理补登补判。
   - 图文核对里结论为“改正文”的行，在本章名词表里找同一对象：名称那边统一的方向和图不一样的，由主代理定方向，必要时发回名称子代理改判。
   - 两个子代理新开的 D 项登记进 `待定决策.md`，需回查的项登记进 `回查清单.md`。
   - 把名称改法、图文改法、其他改法补成 `第NN章-修订规则.json`；改到同一处的，决定留哪条。
   - 只读摘要和脚本输出，不把整章内容拉回自己的上下文。
3. **复核（固定环节）**：用脚本筛出结论是“不同对象”“逐项核对”的行，另派一个子代理只重判这些行，不重读全章。维持的不留记录；推翻的由它直接改那一行、写 `第NN章-复核改法.json`。筛出 0 行时跳过。收活后带上复核改法再跑一遍门禁，补成 `第NN章-复核规则.json`。
4. **写入前问用户**：本章新 D 项和体例待定项一次发给用户（问题、倾向方案、另一选项、处数），等答复后按选择改规则。牵涉后面章节的（如核心名称用哪一个）定了再进入下一章。
5. **写入副本**：机械、修订、复核三份规则预检合并后写入副本。写入后按接受修订后的现文重读修改句及相邻句，检查重复、搭配和含义变化，撤回不必要的修改。图片、公式等不能安全编辑的对象只给定位意见，不声称已修改。
6. **章末汇报**：第几章完成；脚本统计的条数（统一、D 项、待确认、复核改判、修订、批注）；用户本章定了哪些 D 项；覆盖缺口。

**谁兜什么**

| 可能出的错 | 兜底 |
|---|---|
| 漏登：某种写法没被看见 | 门禁第 3 项（变体候选每一对都要看过）；其他问题子代理独立读全章时顺带记下的名称不一致 |
| 判错：该统一的判成了不同对象 | 复核子代理按读者角度重判 |
| 图里的字没拿去正文比、结构图框题对不上模块 | 图文门禁（转写稿里每个标签都要有一行）；逐图核对按图的类型定比对范围 |
| 判了没改全 | 门禁第 2 项（每个非采用写法的位置都要有改法） |
| 改法写错位置或互相踩到 | 补 ctx 脚本和预检；写入后的复读 |

### 阶段 3：回查与章间核对（审了两章及以上时）

1. 处理 `回查清单.md`：后面章节才正式定义的名称、跨章回指，定向读取相关章节核对，结论补入对应章节的改法文件。
2. 各章名词表里同一对象的采用写法两章不同的，按判定原则定统一方向，同样补入，并更新总名词表。

### 阶段 4：汇总报告（用户要求时才出）

从各章名词表和其他问题清单汇总成自包含的 HTML（用户指定格式优先）：审查范围与稿本 → 总名词表 → 明确问题 → 待确认 → 已核查、未核查、范围外。同类问题可合并说明，但每个位置都要能单独定位；涉及图表的问题嵌入原页截图。确认报告能打开、图片清楚、定位正确后再交付。

### 阶段 5：经验入库（需用户同意）

审查结束后列出值得入库的候选案例（漏检、误改、新的边界判例）。用户同意后，按主表“当前不一致的原文—对照依据原文—正确改写—原因梳理”四栏追加到主表，只维护这一份主表。

## 四、D 项怎么管（主代理）

三档处理的定义在 rules.md 第二节。台账只由主代理管：

- **写入前先问用户**：见阶段 2 第 4 步（2026-11-17 用户定）。
- **登记**：子代理返回的新 D 项抄进 `待定决策.md`（编号、问题、倾向、另一选项、涉及章节、状态）。编号不重复即可，可以有空档。
- **沿用**：同一问题在后续章节用同一编号和同一倾向；派单时把涉及本章或全书的行抄给子代理。
- **用户确认后**：状态改为“用户确认”，采用名称写进总名词表；用户选了另一个选项时，按编号在各章改法文件里找出带这个 `decision` 的修订统一改换，后续章节按新方案做。
