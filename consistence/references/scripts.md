# 脚本用法与准备细则（主代理用）

## 环境与位置

- Python：书稿审校技能共用 `~/.venvs/book-review/bin/python`（下文写作 `$P`），依赖见 `~/.venvs/book-review/requirements.txt`。不另装环境，不改用系统 Python；环境损坏时按 requirements.txt 顶部的命令重建。
- 提取、候选、写入的脚本：`~/.claude/skills/editorial-term-consistency-review/scripts/`（下文写作 `$S`）。本技能不另存副本——bianjia、通读技能的脚本都按这个路径调用，两份会改岔。
- 本技能自己的脚本：`~/.claude/skills/consistence/scripts/`（下文写作 `$C`）：`fill_ctx.py`（补 ctx）、`table_tools.py`（门禁、复核筛选、统计）、`fig_gate.py`（图的标签清单、图文门禁）、`slim_glossary.py`（旧总名词表瘦身）。
- 预检脚本在通读技能：`~/.claude/skills/tongdu/scripts/check_rules.py`。
- 工作目录有 `本书配置.json` 的书：准备用 `prep_chapter.py`，机械规则用 `mech_rules.py`，合并和交付用 `merge_chapter.py`，都在 `~/.claude/skills/bianjia/scripts/`，用法见 `~/.claude/skills/bianjia/README.md`。下面“准备”“预检与写入”里的手工命令是没有配置时的做法；判断部分两种做法都适用。

## 准备

### 分章提取

- **DOCX**：`$P $S/dump_docx.py <docx> > source/第NN章-docx段落.txt`。脚本把结果打印到标准输出，每段一行 `P号: 文字`，表格行 `T号: …`，修订标成 `[+插入+]` `[-删除-]`，并标出批注范围。导出的是整份文件；全书一个 docx 时，按可见章题段落的 P 号截出本章再存。
- **PDF**：记下每章的页码范围，供子代理回看原页。分页文字不用再提给子代理（位置一律用 P 号和节号）；只有纯 PDF 稿、没有 docx 时才按页提取文字当正文用。
- 图片化文字、公式、自动编号提取异常的地方，回看 PDF 原页（Claude Code 里用 Read 工具的 `pages` 参数；其他环境把该页渲染成图片再看）。

### 图片导出与转写（有图的章）

1. 导出：`$P ~/.claude/skills/tongdu/scripts/extract_figures.py <底稿docx> source/第NN章-图片 --from <起段> --to <止段>`（有 `本书配置.json` 的书由 bianjia 准备脚本代跑），得到 `图片/*.png` 和 `figures.md`（段号、图题、文件名）。Word 原生图表、EMF 转不了的会列出来，这些看排版页面。
2. 转写：派一个子代理照原图逐张转写成 `source/第NN章-图片文字.md`，只照原样记，不纠错、不判断。每张图一节，格式固定（`fig_gate.py` 按它抽标签）：

```markdown
## 图17-3（P56，图片/P56-1.png）图题：图17-3  多模态投影层
- 图内标题：多模态投影层（上下两个大框顶部）
- 子图标号：无
- 框/节点/标注文字（从左到右、从上到下）：
  - 上行：多模态特征 → 卷积层 → 归一化 → LeakyReLU → 紧凑特征
  - 下行：伪异常特征 → 卷积层 → 归一化 → LeakyReLU
- 箭头/连线上的标注：
  - L_OT（上方虚线双向箭头旁）
- 图例：无图例
- 坐标轴：横轴名、纵轴名、类别标签（逐个列出，用顿号隔开）
- 看不清：无
```

   每项先写图上的字，位置、字体等说明放在后面的括号里；图上的字本身带括号或要逐字强调时用引号“”括起来。
3. 转写完跑 `$P $C/fig_gate.py labels source/第NN章-图片文字.md` 看一眼：每张图都抽到了标签、没有把说明文字当成标签的大量噪音。

### 不可见文字

DOCX 必须先跑 `$P $S/hidden_text.py <docx>`，列出白色、隐藏、极小字号的文字，再对照排版后的 PDF 页面（或渲染页）判断是否可见：

- 下面没有底图的白字是模板占位（丛书名、内容简介、CIP、定价），不可见，不算正文，也不能作为判断依据：不报、不批注、不改，在派单“已知不可见的占位文字”里列出。
- 压在深色标题图上的白字（章题、节号）是可见正文，照常审查。
- 没有 PDF 时把白字列为“可见性待确认”，不直接判断。

### 章切分起点

按章切分时，以**可见的章标题段落**（标题样式）为起点。有的排版稿在章标题图下方另有一行白色的章题副本，起点落在副本上会漏掉真正的章题，修订也会写到不可见的副本上。修订规则里章题的 `ctx` 要能定位到可见的那一段，写入后用 `dump_docx.py` 确认修订落在哪一段。

### 页眉页脚

页眉页脚若是引用章标题的自动域（STYLEREF），改了章标题就会同步，不单独报。

### 脚本候选（派子代理前，每章跑）

- `$P $S/term_candidates.py <段落文件> [图表文字文件] --search <必搜写法,…> [--heads <本书中心词,…>] -o source/第NN章-候选.md`
  按中心词（方法、模型、算法、指标、理论、制度、机构……）把词组分组列出，另列英文缩写前后的称谓（“××算法——EC-TR”“该方法”）和必搜写法的命中位置。`--search` 填总名词表的必搜写法，`--heads` 填本书名词类别清单里的中心词。
- `$P $S/variant_pairs.py <段落文件> [图表文字.txt] source/第NN章-变体候选.md`
  找出本章“只差一个字”的写法配对（换字、增删字、末字换字）。
- 图表文字文件可选，每行 `图1-2: 文字` 或 `表1-2: 文字`，要看 PDF 原页抄录。`variant_pairs.py` 只认以 `.txt` 结尾的图表文字文件，其他后缀会被当成没给。

两份候选是名称子代理“这里可能眼熟”的提示，噪音要它判；变体候选同时是门禁的依据（每一对都要看过）。

## 每章用到的命令

**名词表门禁**（名称子代理交活前跑到 0，主代理收活时再跑；复核后带上复核改法再跑一遍）

```
$P $C/table_tools.py gate 第NN章-名词表.md --rules 第NN章-名称改法.json [第NN章-复核改法.json] --variants source/第NN章-变体候选.md
```

查三件事：结论没判完的行；判了“统一”或 D 项却有位置没写改法的；变体候选里没看过的配对。任一项不为 0 时退出码为 1。

**图文门禁**（图文子代理交活前跑到 0，主代理收活时再跑）

```
$P $C/fig_gate.py gate source/第NN章-图片文字.md 第NN章-图文核对.md --rules 第NN章-图文改法.json
```

查四件事：图没核（转写稿有、核对表没有那一节）；标签没核（抽到的标签在那张图的表里、“不核对：”里都找不到）；结论没写对；判了没落（“→改”“→批注”的行在改法里找不到同 `row` 的条目）。任一项不为 0 时退出码为 1。

**筛出待复核的行**：`$P $C/table_tools.py review 第NN章-名词表.md -o 第NN章-待复核.md`。筛的是结论为“不同对象”“逐项核对”的行；0 行时不用派复核。

**章末统计**：`$P $C/table_tools.py stats 第NN章-名词表.md --rules 第NN章-名称改法.json 第NN章-图文改法.json 第NN章-其他改法.json 第NN章-复核改法.json`。

**补 ctx**（把“段落号＋旧＋新”的改法变成完整规则，写完自动跑预检）

```
$P $C/fill_ctx.py <底稿docx> 第NN章-名称改法.json 第NN章-图文改法.json 第NN章-其他改法.json -o 第NN章-修订规则.json --before 第NN章-机械规则.json
$P $C/fill_ctx.py <底稿docx> 第NN章-复核改法.json -o 第NN章-复核规则.json --before 第NN章-机械规则.json 第NN章-修订规则.json
```

- “没补上”的条目会逐条列出原因。两份改法改到同一处时，后一条会报“前面的规则已经改过这里”，由主代理决定留哪条。
- 整段文字在稿里不止一处（章首目录里的节题、几张表里同名的行）时，脚本取整段作 `ctx` 并加 `exact`，按出现顺序落位；预检会对这类条目报“ctx 不唯一”的提醒，看一眼落的段落号对不对即可。
- 没有机械规则时去掉 `--before` 里的那一项。

## 预检与写入

1. **预检并合并**：`$P ~/.claude/skills/tongdu/scripts/check_rules.py <底稿docx> 第NN章-机械规则.json 第NN章-修订规则.json 第NN章-复核规则.json --merge 第NN章-合并规则.json`
   按写入顺序模拟，查 `ctx` 找不找得到、`old`／`target` 在不在该段、前后规则有没有互相踩到、同段有没有重复批注。错误为 0 才写合并文件。
2. **写入副本**：`$P $S/revise_docx.py <底稿docx> <输出docx> 第NN章-合并规则.json`
   一次只收一份规则文件。在副本上写入最小差异的真实修订和批注，底稿与既有修订不动。写完自动把批注里“x.x.x节“原文””“图x-x“原文””这类位置改成跳转链接，输出末尾列出没对上的——多是引文与正文不一字一致，把批注里的引文改成原句后重跑。
3. **复读**：`$P $S/accept_all.py <修订稿docx> <输出docx>` 接受全部修订（批注保留），再 `dump_docx.py` 导出现文，重读修改句及相邻句。

修订人由脚本自动填：普通修订和批注是“Claude”，带 `"decision"` 的修订是“Claude（建议）”，以【请作者核实】【请作者提供出处】开头的批注是“请作者核实”（Word 里显示另一种颜色）。

## 旧书迁移

前面章节用旧格式审过的书，先把总名词表瘦身：`$P $C/slim_glossary.py 名词表.md -o 名词表-新.md`，人工过一遍采用名称栏（删掉夹带的过程说明），确认后替换。`待定决策.md`、`回查清单.md` 不用改格式，以后只由主代理读。
