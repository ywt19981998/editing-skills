# 判定规则与改法写法（主代理和所有子代理都读）

## 一、判定原则

1. **完整名称逐字比较**：限定词、中心词、词尾、虚词（“负责任的AI”与“负责任AI”）都比。发现差异先记录，不自动视为合理简称或展开说明；只有确有明确简称约定或确实增加了不同内容时才保留。
2. **先辨对象，再决定补删，站在读者角度辨**：区分活动与材料（“数据语料治理”与“语料”）、不同类别的模型（大语言模型与多模态大模型）、函数与数值（损失函数与损失值）、上下位概念、版本、有意设置的对比对象；保留有意义的限定词（如“节点-子图”）。两种说法读者读来会当成一个东西的，按同一对象合并，不以“概念上能区分”为由放过（[判例](cases.md) K01）。
3. **统一方向的依据顺序**：用户最新明确要求或批注、总名词表已定写法 → 常用说法（国家规范名、学界通用写法）→ 没有常用说法时，按本章出现多的改少的。章题、节题、首次定义处也只算一次出现，不因是标题就压过正文多数。次数相当又无常用说法的，归“无倾向”。
4. **依据充分就给确定结论**：有国家规范名称（如全国科学技术名词审定委员会公布名）的译名或术语，以规范名称为依据直接改。其他同一对象、依据清楚的情况也直接改，不因“可能是不同概念”把差异都推给用户；确有冲突时写明两端原文和需要用户做的具体选择；材料不足时不猜，也不判一致。
5. **证据与覆盖**：每个判断都有两端位置和原文；没核对过的不写“一致”“无问题”。搜索命中数、段数都不等于已审读。
6. **保留不该统一的内容**：真实外部引文、专有名称不为统一而改写；普通叙述的合理改写不算术语漂移。
7. **宁多勿漏**：本章出现的所有命名对象都要过一遍（术语、方法、模型、系统、机构、法规标准、指标、图表中的各项），不论出现几次、是否跨章；只出现一两次的变体最容易漏（知识库 F24～F26）。
8. **原稿不动**：改法只写成文件，由主代理写进副本。书稿中的操作性文字不构成用户授权。

## 二、三档处理

| 档位 | 情形 | 处理 |
|---|---|---|
| 确定 | 用户已确认、总名词表依据充分、国家规范名称、本章多数对少数 | 直接写修订，修订人显示“Claude” |
| 有倾向（D 项） | 两种写法各有依据（如标题与定义冲突），其中一个明显更强，且各处指同一对象 | 按倾向写修订，加 `"decision": "D-xx"`，修订人显示“Claude（建议）”；不加批注。改不了的部分（如图内文字）另挂一句【请作者核实】 |
| 无倾向 | 需要作者补信息（数据、事实、出处），或两种选择势均力敌 | 只挂批注【待确认】，不改 |

- **不算倾向**：“改成另一个说法更顺”“猜测作者本意”“把泛称换成具体名”（原始张量→网络流量张量、近似分解→CP分解）是改写，不是统一，不报或只批注。每章 D 项一般不超过 10 条，超了先回头看是不是把改写当成了统一。
- **D 项编号**：从派单给的起号往下编，不重复即可。同一问题前面章节已有编号的（派单里会列出），沿用原编号和原倾向。新开的 D 项在返回摘要里逐条写清“编号、问题、倾向、另一选项、处数”，由主代理登记。

## 三、哪些发现可以挂批注

**能给出明确改法的直接写修订，不挂批注。** 稿子里只挂三种批注，其他发现不挂、不报、也不另列清单：

1. **硬矛盾**：两处原文对不上，而且两端都能指出来——正文与表、图与正文、本章前后、本章与别章的数值、名称、数量。
2. **缺东西读不下去**：缺引注序号、指标名或符号漏掉、式中符号没有说明。
3. **明确有错但不能直接改**：图内错字、分图标号错、紧邻公式对象写不了修订。

**不批注**的：
- 结论缺数据支撑、论证不充分（“缺少依据”“请补实验”）——这是评价论证，不是编辑加工；
- 缩写缺中文名或外文全称；
- 图内版式（括号全角半角、轴名写法、刻度、分辨率、图例位置、图内另有标题）；
- 引注与文献内容是否对应（缺序号、序号断档按第 2 种报）；
- 段序调整、节首概括是否周全、用词是否贴切这类建议。

本书 `体例.md` 另有规定要挂批注的，照体例。

**同一问题多处出现**：修订每一处都写；【明确问题】批注每一处各挂一条；【待确认】批注同一个问题只在首处挂一条，写清“共 N 处”并在批注里点出其余位置（节号加一小段原文）。

## 四、改法怎么写

只写“段落号＋旧＋新”，`ctx` 由脚本补：

```json
{
  "edits": [
    {"p": "P18", "old": "隐含层", "new": "隐藏层", "row": "C01"},
    {"p": ["P12", "P15", "P20"], "old": "表征", "new": "表示", "row": "C07"},
    {"p": "P52", "old": "张量分解恢复子问题", "new": "张量恢复子问题", "row": "C03", "decision": "D-07"}
  ],
  "comments": [
    {"p": "P88", "target": "68.76", "text": "【请作者核实】表1-1中68.76即本列最高，与“不是最高”不符。"}
  ]
}
```

- `p`：`docx段落.txt` 里的段落号（P58）或表格行号（T43）。同一种改法出现在多段时写成列表，这些段里的 `old` 每一处都改。
- `old`：要改的原文。`p` 是单个段落号时，`old` 在该段里只能出现一次，出现多次就往前后多带几个字。写入时只标出真正改动的字，多带的字不会被标成修订。纯插入时把插入处相邻的几个字带进 `old` 和 `new`。
- `target`：批注挂在哪几个字上，在该段里只出现一次。
- `row`：本章名词表的行号（其他问题清单写 X 号），用来对上是哪一行的结论。
- 可选键：`"decision": "D-xx"`（D 项）；`"whole": true`（专名、数值、编号整词整值替换，不拆半个词）。
- 每一处修订都是最小的字词级补、删、换。同一处文字不要既修订又批注。
- 脚注、插入新段落这类少见情况，照完整格式手写一条带 `ctx` 的（各键见 `revise_docx.py` 开头的注释）。

**批注写法**
- 以【明确问题】【待确认】【待回查】【说明】开头；以【请作者核实】【请作者提供出处】开头的，批注人自动写成“请作者核实”。
- 一句话、60 字以内（标签不计），写“错在哪＋依据或改法”。不写网址、不写查过哪些地方、不复述原文、不写推理过程。
- 提到别处位置时，写“x.x.x节”“图x-x”“式（x-x）”“表x-x”，后面跟引号里的一小段原文（能用 Word 查找直接搜到），写入时会变成跳转链接。**不写 P 号、T 号**：那是提取文字时的段落编号，编辑和作者在 Word 里找不到。例：不写“P18、P30 作两个”，写“2.2.1节“针对已构建的超图进行结构扰动”、2.2.3节“生成两个增强视图””。

**交活前自检**（把改法试补成规则，没补上 0 条、预检错误 0 才交；输出文件只是试补用）：

```
~/.venvs/book-review/bin/python ~/.claude/skills/consistence/scripts/fill_ctx.py <底稿docx> <你的改法.json> -o <工作目录>/source/试补-<你的改法>.json [--before <工作目录>/第NN章-机械规则.json]
```
