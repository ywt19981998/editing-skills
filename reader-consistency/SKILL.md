# 读者式一致性审查（试用）

读者发现不一致，不靠一张表，而是**读到这里，想起了前面**：读到“电风场”，想起前面是“风电场”；读到“三个特性”，想起前面只说了两个。本技能只做这一个动作：一个读者子代理按阅读顺序一节一节读，每读到一处就和前文比，对不上的记成疑点，再按正式版一致性的规则落成修订和批注。

本文件只给主代理看。读者子代理不读本文件，只读派单（[读者派单模板](references/reader-prompt.md)）和派单里列的文件。

## 一、范围

- 同一对象的叫法：中文名、英文名、缩写、全称简称、图内标签、表格项、章节题。
- 同一对象前后说的内容：列了几项、是哪几项（性质、组成、步骤、阶段、类别、取值、要求），数值（参数、间隔、阈值、条数），规则和结论。
- 图表和正文：图表放在它出现的位置读，图里的字和正文走同一个回忆过程。
- 前言、目录与正文：前言、全书目录作为阅读材料先读，正文再说到时拿来比。
- 用了没交代：一个词用得像大家都知道，可前文从没交代过。

不在范围内：公式推导与数学符号正斜体、专业事实正确性、措辞润色（另有 runse）、错别字和数字单位写法（另有 tongdu）。

## 二、规则沿用正式版

发现问题的方式换了，处理问题的规则不换，读者子代理直接读正式版的两份文件：
- `~/.claude/skills/editorial-term-consistency-review/references/rules.md`：判定原则（完整名称逐字比、统一方向常用说法优先否则按本章多数、国家规范名称、保留不该统一的）、三档处理与批注门槛、批注写法；
- `~/.claude/skills/editorial-term-consistency-review/references/templates.md` 末节：修订规则 JSON 的写法。

判断“是不是同一个”只看读者角度：读者会以为是同一个东西的，就按同一个比；判“不是同一个”必须写出读者靠哪句原文能分清。

## 三、两张表

| | 全书名词表 | 本章名词表 |
|---|---|---|
| 文件 | `全书名词表.md` | `第NN章-名词表.md` |
| 记什么 | 只记采用名称，以及要改成它的其他写法 | 本章出现的对象：叫法、是什么、列举、数值和规则、不是同一个 |
| 谁建 | 主代理；方向请用户定 | 读者子代理边读边建 |
| 往下传 | 传，每章开读前先读 | 不传；本章审完存档，留给章间核对 |

全书名词表格式（一行一个采用名称，名称族带不带后缀一起改的写在括号里；不记位置、次数、依据、列举）：

```markdown
| 采用名称 | 要改成它的写法 |
|---|---|
| <采用名称甲> | <写法乙>、<写法丙>（带“系统”“电压”等后缀的跟着改） |
```

读者碰到表里“要改成它的写法”，直接改成采用名称，不用再判。

跨章对象靠三样兜：每章审完把定论加进全书表；审完两章以上做章间核对；原文写“第×章所述”的，读者直接翻到那一章核对。

## 四、工作目录

```
<书名>-读者式一致性/
├── source/
│   ├── 前言.txt、目录.txt             # 全书前言、全书目录原文
│   ├── 第NN章-docx段落.txt            # dump_docx 导出、按章截出
│   ├── 第NN章-图片/                   # 本章图片，按位置命名（P28-图1-1.png）
│   ├── 第NN章-图片文字.md             # 照原图转写
│   ├── 第NN章-回忆提示.md             # recall_hints.py 产出
│   └── 底稿.docx                      # 润色后底稿（做过润色时）或原稿副本
├── 全书名词表.md
├── 待定决策.md                         # D 项：问题、倾向、另一选项、处数、状态
├── 第NN章-名词表.md、第NN章-疑点.md、第NN章-修订规则.json   # 读者交回
└── 修订稿/
```

工作目录只放本书材料。别的审查结论（其他技能的名词表、审查记录、修订稿、编辑的答案稿）不放进来；派单里写明不许读工作目录以外的书稿目录。同一章重跑时，先把上一次的产物移出工作目录。

## 五、流程

脚本一律用 `~/.venvs/book-review/bin/python`（下文写 `$P`）。一致性脚本目录 `$S=~/.claude/skills/editorial-term-consistency-review/scripts`。

### 阶段 0：开审前（每本书一次）

1. **固定稿本**：确认文件和审查章节。做过润色（runse）的，在润色后底稿上审。稿中已有修订的，分清修改前、修改后，不把删除和插入拼成一条现文。
2. **前言、目录**：`$P $S/dump_docx.py <前言.docx>`、`<目录.docx>` 导出成 `source/前言.txt`、`source/目录.txt`，目录要全书的，不只截本章。
3. **建全书名词表**：从书名、前言、全书目录、书里已有的术语表或缩略语表，找出要统一的名称，列成“采用名称｜要改成它的写法”。书名、章题核心名称与前言、目录、正文写法不一的，**不许自己预判，先问用户定方向**，定了再写进表。没有前言目录的单章稿，表可以是空的。

### 阶段 1：每章

1. **准备本章材料**
   - `$P $S/dump_docx.py <底稿> > source/全文段落.txt`，按可见的章标题段落截出本章，存 `source/第NN章-docx段落.txt`。
   - `$P $S/hidden_text.py <底稿>` 列出白字、隐藏字；下面没有底图的白字是模板占位，不算正文。
   - 图片：从 docx 的 `word/media/` 取出，按 `word/_rels/document.xml.rels` 和正文里 `r:embed` 的顺序对上位置，按“P号-图号”命名放进 `source/第NN章-图片/`。主代理看原图转写成 `source/第NN章-图片文字.md`，照原图抄、不纠错，看不清标〔?〕，每张图一节：

     ```markdown
     ## 图3-1  图题（P6，第NN章-图片/P6-图3-1.png）
     - 框、标签、箭头方向、数值，逐项照抄
     ```
   - 回忆提示：`$P ~/.claude/skills/reader-consistency/scripts/recall_hints.py source/第NN章-docx段落.txt --figs source/第NN章-图片文字.md --memory 全书名词表.md -o source/第NN章-回忆提示.md`。它按阅读顺序给每段列“该翻前面哪儿”：名字像（差一字、增删字、末字换字、换序、去首字或去尾字的短称、同中心词换限定）、有列举（顿号列举、编号段、“三种”这类数量）、有指代。只是提醒，判断由读者做。
2. **派读者子代理**：Agent 工具 `general-purpose`，前台等返回，不用 fork。提示词照 [读者派单模板](references/reader-prompt.md) 填。派单不用先给用户看。
3. **收活**：
   - 预检：`$P ~/.claude/skills/tongdu/scripts/check_rules.py source/底稿.docx 第NN章-修订规则.json`，错误须为 0，不为 0 就发回同一个读者子代理改。
   - 读返回摘要，必要时抽查疑点表；不把整章内容拉回自己的上下文。
   - 新 D 项登记进 `待定决策.md`。
4. **写入前问用户**（停下来）：把本章新 D 项、体例待定项、读者建议加进全书表的行一次发给用户（问题、倾向、另一选项、处数），按答复改规则。
5. **写入副本**：`$P $S/revise_docx.py source/底稿.docx 修订稿/<文件名>.docx 第NN章-修订规则.json`；再 `$P $S/accept_all.py` 接受修订、`dump_docx.py` 导出现文，重读改动句及前后句，查重复、搭配和同一句里漏改的地方。原稿不动。
6. **更新全书名词表**：用户定了的 D 项、本章统一过且后面章节还会用到的名称，各加一行“采用名称｜要改成它的写法”。
7. **章末汇报**：疑点几条、修订几处、批注几条；用户定了哪些 D 项；全书表加了哪几行；没读到或读不清的地方。

章与章按顺序做（下一章要读更新后的全书名词表）。

### 阶段 2：章间核对（审了两章以上）

把各章的本章名词表并排比：同一对象两章采用的写法不同的，按判定原则定统一方向（要用户定的先问），结论补进各章修订规则，并加进全书名词表。

## 六、试用说明

- 试用期间不设门禁、不加复核子代理；判“不是同一个”的疑点全部留在疑点表，供事后看判得对不对。
- 完整流程（bianjia）仍调正式版一致性，本技能单独点名才用。
- 回忆提示脚本借用正式版的 `variant_pairs.py` 找差一字的写法，两边不另存副本。
- 设计和试跑记录在 `~/Claude/读者式一致性/`（设计草稿、各次试跑对照）。
