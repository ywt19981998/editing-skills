# 公式审校

以**符号含义、原稿属性或原页字形、适用规范**三者共同判断；不对 OCR 文本机械套字体规则。保留原稿，直接改稿须有用户单独授权。

## 一、范围

- 两项审查：①**字形与符号**（正斜体、黑白体、上下标、符号写法、公式与正文符号对应、编号与注释格式）；②**数学正确性**（定义、成立条件、维数与量纲、推导、计算结果）。泛称“公式审校”时两项都做；用户只说正斜体或只说数学正确性时按限定执行，另一项记“未纳入本次范围”。两项分别下结论，不能以一项代替另一项。
- 范围内的**每一页**都要审：编号公式、无编号公式、行内公式、正文里的变量释义、图表里的符号都算。不能只看编号式或只抽几页。
- 程序代码（代码块、行内代码、注释）不审，也不套数学字形规则；算法框中的独立数学公式照常审。台账标“代码，范围外”。
- 纯文字术语、图文一致性属一致性审查专项，不在本技能内。

## 二、准备

1. **固定输入**：记录文件名、哈希、页数、PDF 物理页与书内页码的对应。多个版本内容不一致时列出差异；无法确定基准时问用户，不混用。
2. **PDF 字形扫描（有 PDF 就必跑）**：`scripts/scan_pdf_glyphs.py 书稿.pdf 工作目录/PDF扫描 --crops`。从 PDF 字体信息找斜体的微分号 d、自然常数 e、虚数单位 i、函数名、数字和 π，统计 d 的正斜体是否混用，并输出含公式的页清单 `formula-pages.json`。**Word 里全是 MathType 时，只有这一步能自动查到 d、e、i**。
3. **符号清单（有 PDF 就必跑）**：`scripts/symbol_inventory.py 书稿.pdf 工作目录/符号清单`。逐页列出所有数学字母，正文里夹的单个字母（如“张量 Z”）和全部上下标（i、ij、min、str 等，拆成单独一行的也认得出）都列入；按“符号＋字形＋位置”归组，标出重点候选；自动排除参考文献，列出图片格式的图（要看图）；为每个符号找出定义句，生成符号表模板。脚本几秒跑完，不花 token。
4. **Word 稿（.docx）**：
   - `scripts/scan_omml.py 书稿.docx 输出.json`：Word 自带公式（OMML）的函数名正体、π/e/d 正斜体、撇号、增量、不等号、省略号、乘号编码混用，MathType 与 Word 公式混用的位置。
   - `scripts/dump_docx_math.py 书稿.docx > 全文.txt`：Word 公式转为可读线性文字（⟦ ⟧ 内为公式），便于数学审查。
   - MathType（OLE）和图片公式读不出内容，看 PDF。
5. **排版 PDF 看图**：用 PyMuPDF 把页面渲染为 PNG 后查看（本机没有 pdftoppm）；合成斜体、描边加粗等字体名看不出的情况用 `scripts/prepare_pdf.py` 取逐字符证据。取证方法见 [PDF 取证](references/pdf-style-evidence.md)。
   - **以哪份为准**：用户指定的排版 PDF 是原文，以它的实际字形认定和截图。PDF 只是用户用 WPS 从 docx 导出的时，导出可能换字体造成数字变斜体等假象，与 docx 属性矛盾时以 docx 为准，并在条目里写明两边证据。
6. 默认审校须读 [判定依据](references/judgment.md)、[数学与编辑](references/math-and-edit.md)、[国标速查表](references/guobiao-checklist.md)。

## 三、审查

**字形与符号**

- 先辨语义再判字形：标量、向量、矩阵、函数、集合、单位、索引、描述性下标、几何点线分别判断；同一字母换语境重新判断；主字母样式不自动传给上下标。
- 规范对照 [国标速查表](references/guobiao-checklist.md)。**不以作者习惯或“全书一致”豁免**：微分号 d、自然常数 e、虚数单位 i、圆周率 π 按国标正体，确认语义后斜体即为确认问题，全书统一写错也逐处列出，并在首页注明“全书统一问题，共 N 处”。只有已核实的专门国标条文（如 GB/T 3505 的评定长度 ln）可作例外，记录标准号和条款。
- 确认字形错误须同时有：语义判断、原稿属性或原页字形证据、规范依据。只有其中一部分的列“待专业复核”。
- PDF 扫描和 Word 扫描的候选**逐条**判定（真问题进清单，假候选在台账里写理由），不能只挑几条。
- **符号清单按“符号”判定，不按单个字母判定**：
  1. **填符号表**（`symbol-table.json`）：逐个符号读定义句和例句，填 `meaning`（变量、矢量、矩阵、张量、单位、标签、缩写、说明性下标……）、`expected`（应有字形：斜体／正体／粗斜体／粗正体／花体……）、`scope`（适用页，默认全书）。同一字母含义不同（如 i 既是序号又是虚数单位）写成多条，用 scope 或 position 区分。没有定义句的看例句和整行公式判断。
  2. **自动比对**：`symbol_inventory.py --apply 清单.json 符号表.json`，脚本逐处比对字形，写出判定（正确／错误／部分错误，错误处逐条带页码和位置）。
  3. **剩下的“待判”组**交模型看整行公式和上下文判定，填进同一个判定文件。
  4. 交付前 `symbol_inventory.py --check 清单.json 判定.json`，**有未判定的组就不算字形审完**，写进覆盖缺口。
- `image-regions.json` 列出的图片格式的图，逐张看图检查其中的符号。
- 判断字形以正确渲染的版面为准：MathType 特殊字体（花体、哥特体、空心体）在缺字体的阅读器里会显示成别的样子。

**逐页看图（覆盖）**

- `formula-pages.json` 列出的每一页、以及含图片公式或转曲公式的页，都要渲染原页逐页看，核对扫描查不到的问题（合成斜体、图片公式、黑白体、上下标）。
- 台账逐页记录：字形、数学两项各自是否审完，看不清或语义不明的区域。范围大时分批做，但不能删掉未审页来凑“完成”；没看完的页写进覆盖缺口。

**数学正确性**

- 逐式结合上下文查定义域、成立条件、维数、自由与哑指标、量纲、记号冲突、等价变形和计算结果；区分排印错误、记号冲突、数学错误、缺少条件。
- 验算用共用环境的 **sympy**（符号求导、化简、解方程、求极限）；数值代入只能找反例，不能当证明。注明 sympy 的实数、正数等假设。
- 例题逐题核对“题设—分析—解—结论”是否一致，结论是否回答了所问（如极大还是极小、所求点是否与题设一致）。
- 确定的错误给完整修正式和关键推导；无法确定修正式时保留原式，列“待专业复核”。
- **报给作者或写入正式清单的数学错误须经复核**：独立重新推导，或至少抽验并在交付说明中写明未复核的数量。

## 四、交付

- **独立审校**：默认交付 PDF 审校清单，**一律用 `scripts/export_review.py` 生成，不自己写排版脚本**；格式固定，与 [样例](references/样例-正斜体重审清单前3页.pdf) 一致。**原页截图和红框也由它按每条的 `boxes` 生成，红框为必做项，不自己裁图画框**。记录格式、正确格式的写法、`boxes` 写法、交付前核对见 [清单格式](references/report.md)。用户指定其他格式时从其要求。
- **作为其他审查的一部分**（如初审、编辑加工）：按上级任务约定的格式输出结构化结果（问题、位置、原文、正确写法、依据），不另出公式清单。
- 字形与数学分别给结论和已审范围；确认问题、待专业复核、未核查分开列；未审的不写“无误”。
- 定位以用户确认的 PDF 为准：写 PDF 物理页序号和可见的书内页码、章节、式号和可搜索短句；不按固定偏移推算页码。docx 证据注明“依据 Word 公式属性”。
- 默认不写回 Word 正文、公式对象、修订或批注；其他任务的授权不自动包含公式改稿。用户另行要求改稿时按 [数学与编辑](references/math-and-edit.md) 的“修改源稿”执行。

## 五、环境与工具

- Python 一律用共用环境 `~/.venvs/book-review/bin/python`（Claude 与 Codex 共用，含 lxml、python-docx、PyMuPDF、pdfplumber、pypdfium2、reportlab、sympy；依赖见 `~/.venvs/book-review/requirements.txt`）。不另装环境，环境损坏时按 requirements.txt 顶部命令重建。
- 脚本：`scripts/symbol_inventory.py`（符号清单与逐组判定核对）、`scripts/scan_pdf_glyphs.py`（PDF 字体正斜体扫描）、`scripts/scan_omml.py`（Word 公式属性扫描）、`scripts/dump_docx_math.py`（docx 全文含公式提取）、`scripts/prepare_pdf.py`（PDF 逐字符取证与渲染）、`scripts/export_review.py`（审校清单导出，交付必用）。用法见 [工具说明](references/tools.md)。
