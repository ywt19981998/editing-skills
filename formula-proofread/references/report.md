# 审校清单格式

**所有交付都用 `scripts/export_review.py` 生成，不自己写排版脚本。** 版式已经固定，参照 [样例-正斜体重审清单前3页.pdf](样例-正斜体重审清单前3页.pdf)（用户认可的格式）。导出器不支持的内容，按本文“正确格式的三种写法”处理，不能因此换用自编版式。

用户指定其他格式（如 Word 表格、作为初审的一部分输出）时从其要求；默认只交 PDF，`--formats both` 可同时出 Markdown。公式审校只出独立清单，不写回 Word 正文、公式对象、修订或批注。

## 一、版式（导出器已实现，这里说明给审阅者看）

- **首页**：书名＋清单标题；审查范围；执行技能及字形、数学两项各自的已审范围；确认问题条数（字形、数学分列）和涉及位置数、待复核条数；覆盖状态（未完成时列出缺口）；判据；阅读方法；补充说明（如“全书统一问题：微分号 d 斜体，共 N 处”）；“原稿未修改”。
- **分区**：一、确认问题；二、待专业复核；三、撤回与纠偏记录（有才出）；最后“未核查与覆盖缺口”。每区内按原稿页排序，每个原稿页另起一页，页标题“原稿第 n 页（书内第 m 页）”。
- **每条**：①“编号 类别（字形/数学） 〔n处〕”；②小字“原文定位：……”；③原页局部截图（红框标目标，由导出器按 `boxes` 生成）；④“正确格式：”（待复核区为“条件化建议：”）；⑤灰色小字理由。整条不拆页。
- **页脚**：左“审校类型 · 日期”，右“报告第 n 页”，不与原稿页码混用。

## 二、审校记录 JSON

```json
{
 "title": "《书名》公式审校清单",
 "review_type": "公式审校",
 "date": "2026-10-24",
 "scope": "原稿PDF第1—162页",
 "scope_pages": [1, 2, 3],
 "basis": "GB 3102.11—93……；《作译者指南》（2020）第16、35—37页……",
 "coverage": {
   "complete": false,
   "reviewed": {"字形": "第1—162页逐页看图", "数学": "全部50个编号式及无编号式"},
   "gaps": ["图内细小标注未逐字核验：第45、88页"]
 },
 "source_pdf": "书稿.pdf",
 "notes": ["全书统一问题：微分号 d 斜体，共 29 处，已逐处列出。"],
 "items": [
  {"id": "P020-01", "section": "确认", "kind": "字形", "page": 20, "printed_page": "12", "reading_order": 1,
   "category": "微分号", "count": 2,
   "locate": "2.1.2（7）局部斜率定义式 dZ(x)/dX 中的两个 d",
   "boxes": [{"find": "【d】Z(x)/【d】X"}],
   "correct_runs": [{"text": "d", "style": "upright"}, {"text": "Z", "style": "italic"}],
   "reason": "d 为微分算子，按 GB 3102.11 用正体；Z、X 为变量，保持斜体。"}
 ]
}
```

- `section`：确认 / 待复核 / 纠偏。`kind`：字形 / 数学。字形和数学分开成条，同一处两类问题各出一条。
- `id`：`P页码三位-序号`，如 P020-01；已有台账沿用原编号。`reading_order` 是页内阅读顺序（同区同页递增）。
- `count`：本条涉及的错误位置数，不是截图里的字母总数。
- `locate`：章节、式号或正文句段＋可搜索的短语。
- `source_pdf`：用户确认的 PDF（相对路径按记录文件所在目录算）。截图从它裁取。
- `boxes`：**必填，红框为必做项**，写法见第四节。不再接受自备截图 `image`。
- `elsewhere`（可选）：本条错误位置不全在这一页时（如全章统一问题），写明其余位置，如“第15章式(15-1)～(15-3)等，共 15 处”；导出时接在原文定位后面。
- `page` 为 PDF 物理页序号；`printed_page` 为页面上实际看到的书内页码，看不到就不填，不按固定偏移推算。
- `coverage.reviewed` 分别写字形、数学两项实际审到的范围；`complete` 只有全范围两项都审完才为 true，否则 `gaps` 必须写明缺口。

## 三、正确格式的三种写法（每条三选一）

1. **`correct_runs`**（首选）：按字形分段，`style` 取 upright / italic / bold-italic / bold，`position` 取 normal / sub / super。导出器自动选字体（Times New Roman，缺字时用 STIX Two 补），能排出 ∬、∂、∇、希腊字母、上下标。只写本条要改的目标及必要的邻近符号，其余保持原样。
2. **`correct_image`**：分式、根式、矩阵、长推导等 runs 排不了的修正式，先用可靠方式排好（如在 Word/MathType 里排好后截图，或从原页裁取后改好的公式），存成 PNG 再引用。
3. **`correct_text`**：待复核项的条件化建议，或“保持原式，待补……”。确认问题不用这一项代替修正式。

数学问题的 `reason` 写清相关定义或成立条件、错在哪一步（或反例）、修正依据；无法确定唯一修正式时放到待复核区。

## 四、截图

**截图和红框一律由 `export_review.py` 生成，红框为必做项，不自己裁图、画框。** 每条只写 `boxes`，说明框哪些字：

| 写法 | 用途 | 例子 |
|---|---|---|
| `{"find": "上下文【目标】上下文"}` | 首选。在本页文字层逐行查找（忽略空格，MathType 私用区编码和 Unicode 数学字母已还原），框【】里的字；一个 find 里可以有多个【】；不写【】就框整段 | `{"find": "对【X】执行离散小波变换"}`、`{"find": "#(15−4)"}` |
| `{"find": …, "nth": 2}` | 同一段文字本页出现多次时指定第几处（按阅读顺序） | |
| `{"rect": [x0, y0, x1, y1], "text": "F"}` | 分式、上下标被拆行查不到时，用符号清单 `occurrences` 或扫描结果里的 bbox；`text` 写目标字，导出器收紧到这几个字，免得带上相邻行 | |
| `{"rect": [x0, y0, x1, y1]}` | 图片格式的图、转曲字等没有文字层的区域：看图后给坐标（`image-regions.json` 有图的范围），原样画框 | |

- 导出器按 200dpi 截取红框所在的整行（左右留 6pt、上下 3pt），红框外扩 1.5pt 不压字；需要更多上下文时给 `clip`（页面坐标）或 `margin`。
- **字形条目的红框数不得少于 `count`**；不在本页截图里的位置写进 `elsewhere`。数学条目至少框住出错的式子或步骤。
- 找不到目标、目标在本页不唯一、框数不足、`boxes` 为空时，导出器报错，不出清单，按提示改写 `boxes` 后重导。
- 截图存交付目录 `证据/`，无框原图存 `证据/无框/` 作工作证据。
- `scan_pdf_glyphs.py --crops` 生成的局部图只是定位候选用的，不进清单。

## 五、交付前核对

1. 渲染导出的 PDF，逐页看缩略图，复杂公式和疑点放大看：截图清楚、红框框在该框的字上（导出器只保证框在指定的字上，选得对不对要看）、正确格式无缺字或重叠、整条没被拆页。
2. 条目编号、页码、类别、处数与台账一致，无重复编号、无缺图。
3. 首页的覆盖状态如实：未逐页看图的页、看不清的图片公式、未核的数学式都写进缺口。
4. 告诉用户文件位置、确认问题数（字形、数学分列）、待复核数、覆盖缺口。
